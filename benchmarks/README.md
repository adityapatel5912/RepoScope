# Benchmarks

The harness that produces RepoScope's **published numbers**.

It exists because the 2026 market for code intelligence sells on one
figure — how many tokens does an agent burn to understand a repository?

| Tool | Claimed reduction (Oct 2026) |
|---|---|
| `codegraph` | 62% fewer tokens, 88% fewer tool calls |
| `Repomix` | ~70% reduction (tree-sitter `--compress`) |
| `grepai` | 97% input-token cut |
| `GitNexus` | 88% fewer tool calls (17-agent production audit) |
| **RepoScope** | **not yet measured** ← this directory fixes that |

A claim nobody can reproduce is a liability. This harness exists so every
number RepoScope publishes can be regenerated by anyone.

## Status — Sprint 0

**The harness is a scaffold. It publishes no numbers.**

This is deliberate. Rule S1 in the roadmap says: *never claim a figure the
harness does not produce.* Shipping a scaffold that emits nothing is
honest; shipping a scaffold with a hard-coded number in a README is not.

The runner lands in **Milestone 8.1**, together with the repo map it will
measure:

| Planned output | Produced by |
|---|---|
| `full_context_tokens` — the whole repo read into a prompt | `backend/repo_map.py` |
| `repo_map_tokens` — RepoScope's budgeted map | `backend/repo_map.py` |
| `reduction_pct` | `backend/token_metrics.py` |
| `index_seconds` — time to build the graph | `backend/graph_builder.py` |
| `traverse_ms` — time for a transitive blast-radius query | `backend/impact_analyzer.py` |
| `edge_precision` / `edge_recall` — parser accuracy vs. ground truth | `backend/parsers/*` |

## Planned shape

```
benchmarks/
  README.md          this file — the contract
  corpus/            the repositories the benchmark runs against
  run.py             the runner
  results/           generated output (gitignored)
```

`run.py` will:

1. For each repository in `corpus/`, build the graph and time it.
2. Measure the token cost of the full context versus RepoScope's map.
3. Measure blast-radius traversal latency.
4. Compare the parser's edges against a hand-verified ground truth.
5. Write `results/<timestamp>.json` and a markdown table for the README.

## Rules for this directory

- **No number is written here that the harness does not produce.** If the
  harness has not run, the README says "not yet measured".
- Every measurement is reproducible from a clean checkout with one command.
- The corpus is committed (or pinned by commit SHA) so results are
  reproducible over time.
- Token counts use a named, pinned tokenizer — never a hand-rolled
  estimate presented as exact.
